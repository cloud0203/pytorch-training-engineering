# PyTorch 训练工程

产出可读、可追溯、可恢复、统计口径明确的训练工程。默认采用原生 PyTorch、配置驱动、显式训练循环和轻量模块化；已有项目使用其他训练框架时，沿用其约定，不自行迁移。

## 启用与确认

- 仅在用户明确调用本 skill 时启用，不根据普通训练相关请求自动套用。
- 明确调用表示允许只读分析和提出方案，不自动表示允许修改文件或运行验证命令。
- 完成只读检查后，先给出可审阅方案：拟新增/修改的文件、实现的功能、配置与目录约定、拟执行的检查及是否涉及训练。等待用户明确确认后，才写入文件或执行方案中的验证。
- 用户未回复不视为同意。确认前只继续只读工作；用户只需设计时直接交付设计，不额外要求确认。
- 当前任务中已明确确认的方案无需再次确认；超出已确认范围的新增操作先更新方案并获得确认。
- 请求确认时说明这是用户要求的本 skill 使用规则，并链接本文件、引用对应条款。

## 执行范围

- 用户只要求梳理、prompt 或 skill 时，仅产出相应文档。
- 用户确认实施方案后，编辑确认范围内的代码，完成其中约定的静态检查及不启动训练的轻量测试。明确要求“不要启动训练”时，不运行任何训练试跑，包括 dry-run、smoke test 和间接调用训练的测试。
- 小数据训练验证仅在用户授权范围包含试跑时执行，并限制数据、步数、时间、设备和输出目录。正式训练需要用户已明确要求启动；生成代码本身不表示应启动长时间作业。
- 已有授权持续有效，不重复索要确认。未运行的检查如实标注，不能把静态检查写成训练通过。
- 遵循当前会话及项目的代理协作约定；本 skill 不指定代理模型，也不默认要求子代理。

## 工作流程

1. **读取现状。** 查看项目规则、目录、依赖版本、模型 forward、Dataset/collate、配置、损失与评估代码。优先复用，不覆盖用户修改或迁移数据。
2. **明确任务契约。** 写出输入/输出的 shape、dtype、单位、mask、损失空间、划分单位、主指标及 min/max、硬件和恢复语义。只询问无法从项目中判断且会改变实现的关键信息；其余采用注明的默认值。
3. **选择结构并等待确认。** 阅读 [目录与产物约定](references/project-layout.md)。新工程采用 model/data/logs/weight/scripts/config；已有工程使用等价位置。区分基础能力、启用的扩展和暂不支持的功能。提交拟修改文件、功能和验证范围，取得用户确认后再进入实现。
4. **实现训练契约。** 创建或修改训练代码前阅读 [训练实现规范](references/training-contract.md)。业务部分保留清晰替换点，通用逻辑通过小函数或少量状态类组织。不要建立无必要的注册框架或回调体系。
5. **配置与命令。** 可从 [配置示例](assets/config.example.yaml) 选择需要的字段并适配现有配置格式。示例是设计模板，不是已经存在的执行器；所有交付字段必须实现、校验或明确拒绝，不能静默忽略。
6. **按范围验证。** 使用 [验收清单](references/acceptance.md)，只执行已授权的层级。检查 Python 常规多行格式，运行项目现有 formatter 或适当的格式检查。
7. **交付。** 列出关键文件、实际能力、假设、运行命令、验证证据和未验证项。说明 batch、step、指标、时间与恢复的边界。没有完成的能力不能宣称支持。

## 设计原则

- train.py 负责入口和编排，训练与验证循环易于单独阅读；模型、数据、损失和指标可以替换。
- 配置有唯一生效结果，路径不依赖偶然的 shell 工作目录；实验标识贯通配置、日志和权重。
- 单卡与 DDP 共用主体逻辑；只有全局 rank 0 写共享产物。
- 先定义统计量和分母，再实现跨 batch、跨 rank 聚合；记录本地 step 指标时明确标识。
- 区分 micro-step 与成功的 optimizer-step，调度器、EMA 和 checkpoint 使用一致语义。
- 区分 resume 与 init-from：前者恢复训练状态，后者开始新的训练阶段。
- 不默认开启全部高级功能，不静默改变 batch、损失、采样、精度或数据划分来绕过失败。
- 代码使用常规可读风格，独立语句分行；复杂分支展开，注释重点解释约束和原因。

## 任务差异

- 回归/物理场：区分归一化损失与物理单位指标；处理近零分母、区域权重、无效通道。
- 分类/分割：声明类别映射、ignore_index、类别不平衡及宏/微平均口径。
- 时序：按时间或实体划分，检查窗口重叠和未来信息泄漏。
- 变长序列：按有效 token/元素数归约，正确处理 padding 和累积梯度权重。
- GAN、多优化器或交替训练：明确各优化器的更新频率、scaler 与调度器归属，不能机械套用单优化器循环。

需要不依赖 skill 的整段提示词时，使用 [独立 prompt](assets/standalone-prompt.md)。涉及 API 兼容性时查阅项目安装版本对应的 PyTorch 官方资料；参考来源见 [训练实现规范](references/training-contract.md#参考来源)，不要直接照搬 GitHub main 的 API。
